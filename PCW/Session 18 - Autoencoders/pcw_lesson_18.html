np.random.seed(0)

input_dim = 64
hidden_dim = 8
bottleneck_dim = 2
output_dim = input_dim

params = {
    "layer_1": {
        "W": np.random.normal(size=(input_dim, hidden_dim)) / np.sqrt(input_dim),
        "b": np.zeros(shape=(hidden_dim,)),
    },
    "layer_2": {
        "W": np.random.normal(size=(hidden_dim, hidden_dim)) / np.sqrt(hidden_dim),
        "b": np.zeros(shape=(hidden_dim,)),
    },
    "layer_3": {
        "W": np.random.normal(size=(hidden_dim, bottleneck_dim)) / np.sqrt(hidden_dim),
        "b": np.zeros(shape=(bottleneck_dim,)),
    },
    "layer_4": {
        "W": np.random.normal(size=(bottleneck_dim, hidden_dim)) / np.sqrt(bottleneck_dim),
        "b": np.zeros(shape=(hidden_dim,)),
    },
    "layer_5": {
        "W": np.random.normal(size=(hidden_dim, output_dim)) / np.sqrt(hidden_dim),
        "b": np.zeros(shape=(output_dim,)),
    },
}

# Pay close attention to this function for the next question.
def predict_fn(params, X):
    X0 = X
    # remember, * is an elementwise multiply, whereas @ is a matrix multiply.
    X1 = jax.nn.relu(X0 @ params["layer_1"]["W"] + params["layer_1"]["b"])
    X2 = jax.nn.relu(X1 @ params["layer_2"]["W"] + params["layer_2"]["b"])
    X3 = X2 @ params["layer_3"]["W"] + params["layer_3"]["b"]
    X4 = jax.nn.relu(X3 @ params["layer_4"]["W"] + params["layer_4"]["b"])
    X5 = jax.nn.sigmoid(X4 @ params["layer_5"]["W"] + params["layer_5"]["b"])
    return {'reconstruct': X5, 'bottleneck': X3}

def loss_fn(params, X):
    reconstruct_X = predict_fn(params, X)['reconstruct']
    loss = -(X * jnp.log(reconstruct_X) + (1 - X) * jnp.log(1 - reconstruct_X))
    return jnp.mean(loss)

Question 2a¶

  • How many layers does this network have? 5 (layer_1 through layer_5).
  • Which layer is the "bottleneck layer"? layer_3, its output X3 is only 2-dimensional (bottleneck_dim = 2), far smaller than the 64-dim input or the 8-dim hidden layers.
  • Encoder / decoder layer counts: the encoder (layers before the bottleneck) is layer_1, layer_2, 2 layers. The decoder (layers after the bottleneck) is layer_4, layer_5, 2 layers.
  • Why "encoder" and "decoder"? Same naming as compressing/decompressing a signal. The encoder takes the 64-dim input and compresses it down to the 2-dim bottleneck code. The decoder takes that compressed code and expands it back out into a 64-dim reconstruction.
  • Why return {'reconstruct': X5, 'bottleneck': X3}? X5 is needed to compute the reconstruction loss, it's literally what the network is trained against. X3 is the actual payoff: the compressed 2-number summary of the input. It isn't used in the loss directly, but it's the whole reason autoencoders are useful (visualization, compression, downstream use), and it's small enough (2D) to plot directly, which Question 4 does below.

# We use an optimizer called Adam here.
# We won't go into detail, but think of it as "fast gradient descent"
optimizer = optax.adam(1e-3)
opt_state = optimizer.init(params)

grad_loss_fn = jax.grad(loss_fn)
grad_loss_fn = jax.jit(grad_loss_fn)

np.random.seed(1)
for i in range(total_steps):
    idxs = np.random.randint(low=0, high=x_data.shape[0], size=32)
    x_batch = x_data[idxs]
    # Remember, we compute gradients of the *first* argument, which is params.
    grad = grad_loss_fn(params, x_batch)
    update, opt_state = optimizer.update(grad, opt_state)
    params = optax.apply_updates(params, update)

    # We print the loss every 100 steps
    if i % 100 == 0:
        loss_val = loss_fn(params, x_data)
        print("Step:", i, "Loss:", loss_val)

print("FINAL LOSS:", loss_fn(params, x_data))

Question 3¶

x_data has 1797 examples; tried several EXAMPLE_NUMBER values above (and the per-class breakdown below confirms it across all of them, not just one spot-check).

Reconstructions are recognizable but blurry, smoothed-out versions of the originals: overall digit shape is preserved, fine stroke detail is lost. Verified per-example MSE: mean 0.055 (std 0.019) across all 1797 digits (exact numbers above). Quality isn't uniform across digits: digit 3 reconstructs best (mean MSE ~0.04), digit 7 reconstructs worst (mean MSE ~0.076), with digit 5 close behind. The flaw is structural, not a bug: squeezing every digit through a 2-number bottleneck means only the 2 most informative "directions" of variation survive, so digits with more complex or more variable handwriting (7) lose more than simple, consistent shapes (3).

Question 4¶

Bottleneck vectors of the same digit are closer together than vectors of different digits. Verified: mean pairwise distance between same-digit points = 2.08, mean pairwise distance between different-digit points = 3.80, nearly double (exact numbers above).

This is notable specifically because the model never saw the labels, it was only trained to reconstruct each image from itself (loss_fn only ever compares reconstruct to the original x_data, y_data never appears in training). The clustering by digit identity emerged purely as a side effect: digit shape (what actually drives reconstruction quality) happens to correlate strongly with digit label, so compressing for reconstruction accidentally discovered class structure too, without ever being told what the classes were.
